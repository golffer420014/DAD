# แนวคิดโปรเจกต์ (Project Concept)

> **นี่ไม่ใช่ dashboard วิเคราะห์ข้อมูล** — สรุปสั้น ๆ ว่างานนี้คือ "แยกเนื้อดีเนื้อร้าย แล้วส่งมอบต่อ"

## โปรเจกต์นี้คืออะไร

เครื่องมืออำนวยความสะดวกให้กับงานหวยใต้ดิน สำหรับขั้นตอนที่เกิดซ้ำทุกงวด คือการ **รวมยอดโพย** จากลูกข่ายหลายคน แล้วส่งต่อขึ้นสายบน

## ใครใช้งาน (User)

**Downline** คนหนึ่งที่:
- รับชุดข้อมูลการซื้อเลข (โพย) จากลูกข่ายของตัวเอง **4-5 คน** ต่องวด
- ข้อมูลแต่ละคนมาเป็นไฟล์ Excel แยกไฟล์ (ดูตัวอย่างจริงใน [`docs/`](.) — เช่น `16 สค 69 ติ๊ก.xlsx`, `ปุ๋ย1.xlsx`)
- ต้องส่งชุดข้อมูลที่ผ่านการคัดกรองแล้วต่อให้ downline ตำแหน่งสูงกว่า (สายบน)

## รูปแบบข้อมูลต้นทาง

ไฟล์ Excel จากลูกข่ายแต่ละคนมีโครงสร้างคอลัมน์ตรงกัน (sheet แรก):

| เลข | บน | ล่าง | โต๊ด |
|-----|-----|------|------|
| 27  | 30  | 30   | 0    |
| 927 | 30  | 0    | 0    |

- **เลข** — เลขที่ซื้อ (2 หลักหรือ 3 หลัก)
- **บน** — ยอดซื้อ "บน"
- **ล่าง** — ยอดซื้อ "ล่าง" (เฉพาะเลข 2 หลัก)
- **โต๊ด** — ยอดซื้อ "โต๊ด" (เฉพาะเลข 3 หลัก, ถูกได้ทุกการเรียงสลับ)

แต่ละไฟล์มักมีแถวเทมเพลตของเลขที่เป็นไปได้ทั้งหมด (~1,500 แถว) โดยมีค่าจริงเฉพาะแถวที่ลูกข่ายซื้อ ส่วนที่เหลือว่างเปล่า — ไฟล์ที่คุณภาพไม่ดี (เช่น `เมย์.xlsx`) อาจมีคอลัมน์เลขหายไป ต้องรับมือกรณีนี้ด้วย

## Workflow (3 ขั้นตอน)

### 1. นำเข้า & รวมยอด (Import & Merge)
Import ไฟล์ Excel ของลูกข่ายทุกคนพร้อมกัน แล้วรวมเป็นชุดข้อมูลเดียว:
- เลขเดียวกันจากหลายไฟล์ → รวมยอด บน/ล่าง/โต๊ด เข้าด้วยกัน
- ทดแทนขั้นตอนเดิมที่ user ต้องเปิดทีละไฟล์แล้วรวมยอดเอง

### 2. คัดกรอง / กั๊ก (Triage & Hedge)
จากชุดข้อมูลที่รวมแล้ว user จะ **เลือกเอง** ว่าเลขไหนจะ "กั๊ก" ไว้กับตัวเอง (ไม่ส่งต่อ) โดยพิจารณาจาก:
- เลขที่โอกาสถูกรางวัลต่ำ
- เลขที่ยอดซื้อไม่สูง

การตัดสินใจนี้เป็น **ความเสี่ยงที่ user เลือกรับเอง** ไม่ใช่การแนะนำอัตโนมัติจากระบบ — เครื่องมือมีหน้าที่ทำให้ user เห็นชุดข้อมูลรวมและเลือกได้สะดวก ไม่ใช่ตัดสินใจแทน

### 3. ส่งต่อ (Forward / Handoff)
ส่งชุดข้อมูลที่เหลือ (หลังตัดเลขที่กั๊กออกแล้ว) ให้ downline ตำแหน่งสูงกว่า → จบงาน

## สิ่งที่ไม่ใช่ (Non-goals)

- **ไม่ใช่ analytics dashboard** — ไม่ต้องมีกราฟสรุปเชิงวิเคราะห์ที่ไม่ตอบโจทย์งานจริง เช่น bar chart "เลขยอดนิยม" (top numbers by frequency) เพราะ user ไม่ได้ต้องการรู้ว่าเลขไหนถูกซื้อบ่อย เขาต้องการ **คัดแยกและส่งต่อ**
- ไม่ใช่เครื่องมือให้ insight เชิงสถิติระยะยาว ไม่ต้องมีการเก็บ trend ข้ามงวด
- เป้าหมายคือ **ลดความซ้ำซ้อนของขั้นตอนทำงาน** (รวมยอดมือ → คัด → ส่ง) ไม่ใช่การรายงานผล

## ศัพท์ที่ใช้ (Glossary)

| คำ | ความหมาย |
|---|---|
| ลูกข่าย | ผู้ซื้อเลขที่ส่งโพยขึ้นมาให้ user (ต้นทางข้อมูล) |
| ดาวน์ไลน์สายบน | ผู้รับข้อมูลที่ user ส่งต่อไป (ปลายทาง) |
| เลข | หมายเลขที่ซื้อ (2 หรือ 3 หลัก) |
| บน / ล่าง / โต๊ด | ประเภทของการซื้อ (ดูตารางด้านบน) |
| กั๊ก | การเก็บเลขไว้เอง ไม่ส่งต่อขึ้นสายบน เพื่อรับความเสี่ยง/ผลตอบแทนเอง |

## ประเด็นที่ยังต้องตกลงกันต่อ (Open questions)

- **เกณฑ์ "โอกาสถูกรางวัลต่ำ"** — หมายถึงอะไรที่วัดได้จริง (เช่น ประเภทเลขบางกลุ่ม, เลขที่ไม่อยู่ในสถิติออกบ่อย) หรือปล่อยให้ user เลือกเองล้วน ๆ จากยอดซื้อ?
- **รูปแบบไฟล์ที่ส่งต่อ** — ส่งเป็น Excel ไฟล์ใหม่ที่ export ออกมา หรือรูปแบบอื่นที่สายบนต้องการ?
- **จำนวนไฟล์ต่อรอบ** — ตายตัวที่ 4-5 ไฟล์ หรือควรรองรับจำนวนไม่แน่นอน?
